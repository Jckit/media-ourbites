# Ourbites motion craft

A selective HyperFrames-derived design adapter, implemented with Remotion. No HyperFrames runtime, GSAP, CLI, registry or templates are required.

Keep the workflow: Research → Script → Creative Director → Motion Design → Codex/Remotion → Narration/SFX/Captions → Render → Viewer Review. Timing estimates become measured audio cues before narration lock.

- **Creative Director:** what the viewer sees and why; owns staging and the reading goal.
- **This adapter:** how movement expresses that goal; authors poses, curves, continuity and contact.
- **Codex + Remotion:** implements through existing components and frame-driven APIs.
- **Viewer:** evaluates actual rendered media; code and sampled stills cannot establish playback quality.

Read only the relevant reference:
- [Choreography](references/choreography.md): key poses, easing, motion paths, handoffs, masks, camera and contact.
- [Composition](references/composition.md): hierarchy, typography, holds and encoded-media checks.
- [Provenance](references/provenance.md): pinned upstream sources, license and exclusions; only for audit/update.

Use the existing [motion skill](../../../skills/ourbites-motion/SKILL.md) and [Creative Director](../../../skills/ourbites-creative-director/SKILL.md) for architecture and approvals.

Record decisions in the existing animation ticket, not another planning document: goal, coordinate owner, key poses/times, curve by role, contact/occlusion, protected text, narration cue, acceptance frames. Reuse existing scene anchors and canonical host. Preserve factual labels, voice and human gates. Test one evidenced change with matched before/after output; keep candidates unapproved. Do not promote a sample-specific recipe into the shared library without its existing reuse and human-review requirements.
