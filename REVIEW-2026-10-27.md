## Findings

1. **P1 — release cast validation does not bind approval to an existing asset.** `scripts/validate_character_cast.py:95` and `:102` check only that reviewer and asset_sha256 are nonempty. In a temporary fixture, `approved=true`, reviewer `test-only`, and hash `not-a-hash` passed `release=True` with no asset present. Require a valid SHA-256 and compare it with the actual canonical asset/implementation file, or explicitly delegate to a mandatory verified release preflight. Never create approval metadata automatically. The present validator describes itself as structural, but its release option still cannot establish that the released asset matches the approved version.

2. **P2 — preview workflow does not watch all cast dependencies.** `.github/workflows/anthropic-preview.yml:6` omits `characters/**`, `scripts/validate_character_cast.py`, `scripts/verify_anthropic_media.py`, `src/index.tsx`, and package dependency files. A profile or validator-only change will not generate a refreshed preview. The general validation workflow still runs on main/PRs; this is a preview-trigger gap, not a total absence of CI.

3. **P2 — numerical animation regression test is absent from CI.** `.github/workflows/validate.yml` runs Python tests and TypeScript but not `tests/ownership-state.test.mjs`. Typechecking cannot detect the intermediate-frame inconsistency this test was written to catch. Add its Node test command using a Node version supporting type stripping.
